Workflow

  1. Draw a directed state transition diagram, or type or paste its text in the editor on the left — both views stay in sync. The drawing is redrawn automatically a moment after the text changes; states without an at (x, y) position are laid out automatically. If the text has a syntax error, the last valid drawing stays until it is fixed (see the problems list under the editor).
  2. Declare the attributes (atoms) in the Attributes tab and give them a value in each state.
  3. Mark one or more initial states (double border).
  4. Enter properties (LTL, CTL or invariants) and optional fairness constraints.
  5. Check with nuXmv. False properties come with a counterexample that can be replayed on the diagram.
  6. Run it: the Python tab generates an implementation that only allows the verified transitions and monitors the properties, a Jupyter notebook with a live diagram, property-based tests, framework exports (XState, LangGraph, Burr, Temporal) and NuRV monitors.
  7. Operate it: Trace → Live from Python follows (and drives) a running process; Check a recorded run compares a real execution with the model.
  8. Quantify it: with transition probabilities, the Properties tab computes how likely and how fast goals are reached.

Each of these has a . Existing LangGraph, CrewAI, Mermaid or XState graphs can be imported with File → Import agent graph.

Drawing board

  • Select mode: click to select, drag to move, drag on the background to box-select, double-click the background to add a state.
  • State mode: every click on the background creates a state.
  • Transition mode: drag from a state to another (or back onto itself for a self-loop).
  • Mouse wheel zooms, dragging the background pans. Delete removes the selection.
  • Drag the dividers around the diagram to resize it (arrow keys work when a divider has focus; double-click resets it). ⤢ gives the diagram the whole window; Esc brings the panels back.
  • Dashed border: dead-end state (no successor). nuXmv needs every path to be infinite, so the generated model makes it loop on itself.

Text syntax (.pflow)

diagram ResourceMonitor

attributes {{ '{' }}
  status  : {{ '{' }} ready, busy {{ '}' }};   // enumeration
  request : boolean;
  level   : 0..3;              // integer range
{{ '}' }}

initial state s0 "idle" {{ '{' }} status = ready, request = TRUE {{ '}' }} at (80, 80)
state s1 {{ '{' }} status = busy {{ '}' }}

s0 -> s1 : "request";
s1 -> s0;

FAIRNESS request;
LTLSPEC G (request -> F status = busy);
CTLSPEC NAME reset := AG EF state = s0;
INVARSPEC level <= 3;

// Data: bounded variables changed by transitions with guards, updates and probabilities
variables {{ '{' }} retries : 0..3 := 0; approved : boolean := FALSE; {{ '}' }}
s1 -> s0 : "retry" when retries < 2 do retries := retries + 1 prob 0.3;

Expressions use the nuXmv syntax: ! & | xor -> <->, comparisons, LTL G F X U V and CTL AG AF AX EG EF EX A[p U q] E[p U q]. The variable state holds the current state name.

Engines

  • BDD: exact symbolic model checking of all specifications (default).
  • BMC: bounded model checking of LTL properties up to the given bound — finds short counterexamples, cannot prove properties.
  • IC3: SAT-based proofs of invariants and LTL properties; CTL is still checked with BDDs.
